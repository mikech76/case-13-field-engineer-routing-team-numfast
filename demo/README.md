# ДЕМО — запуск и сценарий показа

## Запуск

```bash
cd site
python -m http.server 8080
# открыть http://127.0.0.1:8080/
```

Требуется только статический сервер. Ни пакетов, ни ключей, ни бэкенда.
Интернет нужен **только** для подложки карты (Esri/OSM). Если его выключить,
подложка пропадёт — все цифры, маршруты и распределение останутся.

## Что происходит при открытии

Страница сама:

1. грузит 15 `.bin` в линейную память WASM — **0.4 с**;
2. привязывает 177 точек (100 заявок + 77 бригад) к дорожному графу —
   **медиана 62 м, 177 из 177**;
3. считает 132 Дейкстры по портальному графу — **8.2 с**;
4. запускает S0 — **34 мс**;
5. рисует 97 дорожных ломаных — **1.6 с**.

Прогресс виден в верхней панели, каждый этап с миллисекундами.

## Сценарий показа (2 минуты)

**1. Общий план.** Открывается сетка-таймлайн: слева KPI, справа воронка отказов.
Показать цифры: **97 / 100, 24 бригады, 323.6 км по дорогам, 0 нарушений**.
Обратить внимание на строку под воронкой: `времён: портал 36 960 · точная матрица 0 ·
без ответа 422` — **98.9 % времён точные**, остальное честно помечено.

**2. Воронка отказов.** Три заявки в хвосте области (Кашира, Домодедово) помечены
`портальный граф не перекинул мост`. Это **не списано в молоко** — ровно то, что
просит вопрос 49: отметить, что не влезло. Здесь же можно предложить +N исполнителей.

**3. Маршрут бригады.** Кликнуть бригаду в левом списке (или заявку на карте, или
заявку в сетке). Правая панель показывает маршрутный план: сегменты по порядку,
время прибытия, адрес, километры, тег **ДОРОГИ** или **ПРЯМАЯ**. На карте
выделяется только маршрут этой бригады — сегменты разными цветами, на концах
стрелки направления.

**4. Один сегмент.** Кликнуть сегмент в правой панели **или прямо по нему на
карте**. Камера плавно уезжает, сегмент занимает три четверти экрана, по нему идёт
бегущий пунктир. Остальные сегменты остаются со своими стрелками.

**5. Пробки.** Тумблер «Пробки вкл/выкл» в верхней панели. Выключить и включить —
видно, как меняются времена в сегментах. Подписано: `city-uniform 2015`, и в
README честно сказано, что реальные замеры только k(09) и k(19), остальное
интерполяция.

**6. Масштаб.** Переключатель «100 / 1000 заявок» в верхней панели.

## Что говорить, если спросят

**«У вас 97, а не 100 — почему?»**
Три заявки в хвосте области не сцепляются в кластерной цепочке. Мы не ставим на
них прямую линию и не подставляем выдуманное время — они уходят в воронку с
причиной. Вопрос 49 это прямо разрешает.

**«Откуда такие километры?»**
Кратчайший путь по дорожному графу ЦФО, не хаверсис. Проверено против точного
Дейкстры на полном CSR: медиана расхождения +0.6 %, хвост +7 %.

**«Пробки настоящие?»**
`k(h)` равномерный по городу, на реальных значениях ymarchive 2015 для двух часов
пик и интерполяции между ними. Порэберный слой к рёбрам OSM не привязан — это
честно написано в README и в самом интерфейсе. Слот заменяемый.

**«А OR-Tools?»**
Сознательно не взяли (вопрос 52 это допускает). Взятый OR-Tools на той же задаче
даёт 178 заявок / 803.9…816.1 км за 3 × 5…120 с. Наш S0 — 179 / 580.0 км / 0.10 с.

## Чего в стенде нет (и почему)

* обед в кафешке — есть в `SEGS_CONTRACT.md` как `kind=lunch`, но в самом стенде
  за неделю до сдачи не разводили;
* порэберные пробки — растровый слой не привязан к рёбрам;
* транзитные перегоны между остановками — считаются тем же Дейкрой, но не
  показаны отдельным типом ноги.
